# e01s01: Bootstrap generator
## 1. Identity
Feature, infra, P0, maturity 3, 5 BCPs.
## 2. Context
Repository contains only a license and an untracked PLAN.md; prior completion claims are not implementation evidence.
## 3. Goal
Deliver the approved minimal generator and first unchecked golden-test task.
## 4. Actor
Agent developer with Python 3.11+.
## 5. Preconditions
npm package-lock.json and start script, or requirements.txt and explicit relative Python file entry point.
## 6. Trigger
python3 -m agent_dockerizer dry-run PROJECT or generate PROJECT.
## 7. Requirements
### ADDED: Supported inputs
Detect node/python stacks, generic/pi/opencode profiles, with profile override; reject ambiguity.
### ADDED: Generated artifacts
Produce deterministic Dockerfile, Compose, environment example, build workflow and Docker ignore file.
### ADDED: Safety
Never interpolate secret values; dry-run does not write; generation refuses existing files and symlink destinations.
### ADDED: Golden coverage
All six supported stack/profile pairs have fixtures and reviewed expected output for every artifact.
## 8. Outputs
Five UTF-8 files with LF endings; stdout dry-run preview or generation filenames.
## 9. Contracts
Same supported input/options gives identical bytes; no timestamps, project paths, or secret values in templates.
## 10. Design
Small detection/rendering module plus CLI I/O. Reason for Depth: one render path guarantees dry-run/write equivalence.
## 11. Dependencies
Standard library only. Runtime/action dependencies and [OK] tags are in tech-stack.md.
## 12. Security
Treat project content as untrusted; validate entry paths; reject symlinked inputs and output ancestors; conventional secrets excluded from build context.
## 13. Steps
1. Detect inputs and render fixed templates with golden tests → verify: `python3 -m unittest discover -s tests -v`
2. Add safe dry-run and generation CLI → verify: `python3 -m unittest discover -s tests -v`
3. Document invocation and wire CI → verify: `python3 -m unittest discover -s tests -v`
## 14. Verification script
Run unittest, dry-run a fixture, copy fixture to temporary directory and generate, validate Compose, optionally build with Docker.
## 15. Out of scope
Package publishing, remote deployment, launch materials, extra package managers, compiled npm builds, arbitrary Python packaging.
## 16. Risks
Dependency installation requires network; conventional ignore patterns cannot detect secrets embedded in arbitrary source. GitHub CI needs a push and is not proved by local tests.
## 17. Acceptance criteria
All six combinations match all five goldens; repeated outputs identical; fixture secret sentinels absent from stdout/stderr/files; no overwrite; symlink rejection; unsupported inputs give actionable errors.
## 18. Test strategy
Independent temporary directories, public CLI/API tests, fixed goldens never regenerated by normal tests.
## 19. Red flags
Do not mark historical PLAN.md claims newly verified. Do not bless actual output as expected without independent template review.
## 20. Handoff
Only mark tasks passing after command exits zero; retain remote CI as pending until actual evidence.
